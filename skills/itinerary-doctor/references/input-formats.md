# 支持的输入形状

真实用户的行程来自各种地方：自己做的表、AI 生成的 markdown、微信聊天记录、手打的一段话。
本 skill 用**三级策略**自动识别，命中即停（可靠性优先），并会把"用的是哪一级"写进输出。

## 支持矩阵

| 输入形状 | 例子 | 现状 | 用哪级策略 |
|---|---|---|---|
| 标准表格（中文表头） | 日期 / 建议出发 / 当日路线 / 住宿 | ✅ 自动 | 表头映射 |
| 标准表格（**英文表头**） | `Date,Plan,Stay` | ✅ 自动 | 表头映射 |
| 表头词不标准 | `时间,安排` | ✅ 自动 | 表头映射 |
| **无表头**表格 | `9月25日,抵达乌鲁木齐,全季酒店` | ✅ 自动 | 按列位置猜（首列日期 + 次列内容 + 末列住宿） |
| **天序号 + 日期 + 内容** | `第1天,9月25日,抵达乌鲁木齐,全季酒店` | ✅ 自动 | 按列位置猜（识别出次列才是日期） |
| Excel **日期序列号** | 单元格里是 `46290` | ✅ 自动还原为 2026-09-25 | 表头映射 / 位置猜 |
| **多工作表** xlsx | Sheet1/Sheet2 都有数据 | ✅ 自动取"能解析出天数的那个" | 逐表尝试 |
| **markdown 标题式** | `## Day 3 · 9月27日 🏔 布尔津 → 白哈巴` | ✅ 自动 | 标题式（含 emoji 清理） |
| 中文标题式 | `第3天 布尔津—白哈巴` / `**第三天**` | ✅ 自动 | 标题式 |
| **散文 / 聊天记录** | "9月25号到了乌鲁木齐先住一晚，26号开车去布尔津……" | ✅ 自动 | 散文式（**以日期为锚点切段**） |
| PDF | — | ⚠️ 需先转成文本/表格 | 复制文本出来即可走上面任一条 |
| **截图 / 照片** | 微信里发来的图片版行程 | ❌ 不能 | 见下 |

## 日期识别能力

| 写法 | 支持 |
|---|---|
| `2026-09-25` / `2026/9/25` / `2026.9.25` / `2026年9月25日` | ✅ |
| `9月25日` / `9月25号` / `9/25` / `9.25` | ✅（用 `--start` 或表里其他日期补全年份） |
| `26号`（省略月份） | ✅ 按上文月份顺延，跨月自动进位 |
| `第3天` / `Day 3` / `D3` / `第三天` | ✅（`第 N 天` 需配 `--start 2026-09-25` 换算成真实日期） |
| `国庆第二天` / `中秋` / `下周` 这类相对说法 | ⚠️ 不认，需人工换成日期 |

## 为什么截图不能自动处理

不是脚本的问题，是**读图**这一环：本 skill 只做解析与渲染，不做 OCR；而很多 agent 环境里的模型
并没有视觉能力（本项目开发时用的环境就是如此——测试中图片会被服务端直接丢掉）。
所以遇到截图请走这两条之一：

1. 让用户把图里的文字**贴成文本**（微信长按可"提取文字"），再走散文策略；
2. 换用**有视觉能力的 agent** 先把图片转成表格或 Day 标题文本，再交给本 skill。

## 自动判断不对劲时怎么办

先看输出里的"命中策略"那一行，再强制指定重跑：

```bash
python scripts/parse_itinerary.py 行程.md --strategy heading
python scripts/normalize_input.py 行程.txt --strategy prose --start 2026-09-25
```

`--strategy` 可选 `table` / `heading` / `prose`。三级策略的定义与实现见
`scripts/normalize_input.py` 头部注释。

## 这层是被测试锁住的

`tests/fixtures/` 里固化了 6 种真实脏输入样本，`tests/test_normalize.py` 断言它们各自
命中预期策略、解析出预期天数与关键字段（含真实案例的 Excel 序列号日期回归）：

```bash
python tests/test_normalize.py
```

改解析逻辑后请先跑它——早先的版本就是因为没有这层测试，才会出现"6 种常见输入 6 种全挂"
而没人发现。
