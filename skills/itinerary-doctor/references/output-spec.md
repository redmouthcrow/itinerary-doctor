# 交付物规格

一次体检产出四件东西。前三件由脚本生成，第四件由 agent 撰写。

| # | 交付物 | 生成方式 | 给谁看 |
|---|---|---|---|
| A | **单文件交互路线图** `路线图.html` | `render_html.py`（零依赖） | 终端客户：能点、能缩放、可转发 |
| B | **行程报告** `行程报告.md` | `render_report.py` | 客户/同事：退改决策 + 避坑清单 + 逐日计划 |
| C | **路线海报** `路线图.png` | `render_poster.py`（可选，需 Pillow） | 打印、发群、做营销素材 |
| D | **行程计划书** | agent 撰写（可并入 B） | 完整交付文档：理由、备选方案、待办 |

---

## A. 交互路线图（`trip.json` → HTML）

必须满足：

- [ ] **单文件**：Leaflet 与 CSS 内联，双击即开，不依赖任何服务器或 CDN 之外的本地文件
- [ ] 底图用高德瓦片，坐标已从 WGS-84 转成 GCJ-02（不转会整体偏移 300—600 m）
- [ ] 按天配色；**同一段路往返两次**用平行偏移分开画（偏移是地理距离，总览时会合拢）
- [ ] 编号途经点 + 弹窗；点击侧栏日程可聚焦当天路线并高亮
- [ ] 侧栏包含：订房动作清单、逐日计划、避坑提示
- [ ] 瓦片加载失败时给出可见提示（**不要静默留一片灰**）
- [ ] 页脚保留"Generated by itinerary-doctor"（这是唯一的传播位）

验收：在任何浏览器打开，标注数量 = `stops` 数量，点击每个日程都能聚焦。

## B. 行程报告（Markdown）

必须包含五节：订房与退改决策 / 逐日计划 / 避坑清单（按 `hard → stale → soft` 分组）/ 待核实与风险项 / 免责。

**退改决策表**的写法要求：
- 用动词开头：保持不变 / 退订 / 改期 / 新订
- 写清楚**处理顺序**（先订稀缺资源 → 再谈改期 → 最后退订），因为退订越晚越可能错过免费取消窗口
- 不可退改的项要明确写"当作沉没成本"，并给出替代方案

## C. 路线海报（PNG，可选）

- 自动选缩放级别（默认瓦片数上限 220），自动取行程范围
- 标题 + 副标题 + 提示行 + 地图 + 底部逐日表 + 比例尺
- 标签自动避让，且不能越出画布
- 没装 Pillow 时**优雅跳过**并提示安装命令，不影响其余交付物

## D. 行程计划书（agent 撰写）

由 agent 在 B 的基础上补充：为什么这么改（一句话人话）、被砍掉的段落的理由、
备选方案（如果某个预订卡住怎么办）、以及按时间倒排的**待办清单**。

---

## 全局质量红线

1. **里程必须来自真实路网**；退化过的路段必须在报告与地图上都标出来。
2. 时效信息带**来源 + 核实日期**；过期的标「待核实」，不得改写成确定语气。
3. 不确定项写"以景区当日公告为准"，并给出官方咨询电话（如喀纳斯 400-111-0906）或 12328。
4. 交付前**在浏览器打开一次 HTML**，确认瓦片、标注数、交互三项都正常。
5. 任何一处"我猜的"都要在 `_draft.must_review` 里留痕。
